## 1. Executive Summary

KPIA is a generative-AI product-information assistant intended to help Kentainers sales representatives find relevant product information, clarify incomplete customer requirements, and respond using available catalogue evidence. The project combines a conversational web interface, an LLM-based agent, structured product-search tools, and retrieval-augmented generation (RAG). It is designed to avoid unsupported claims and escalate when evidence is insufficient.

The repository includes application source, evaluation assets, a reported 110-question product-intelligence test bank, regression cases, and agent/tool scenarios. Final runtime metrics and complete end-to-end evaluation must be generated from actual execution.

## 2. Problem and Target User

Sales representatives and product-information staff receive customer questions with incomplete requirements or requests for specifications that may not be present in approved product information. KPIA is designed to speed up product discovery and provide consistent, evidence-grounded guidance. Primary users are Kentainers sales representatives and staff supporting customer product enquiries.

## 3. Objectives

- Provide a conversational product assistant.
- Retrieve Kentainers catalogue information.
- Use structured product-search and product-detail tools.
- Ask clarifying questions when intent is ambiguous.
- Avoid inventing unsupported facts.
- Record enquiries for follow-up.
- Evaluate behavior with repeatable RAG and agent/tool test assets.

## 4. Solution and Agentic Capabilities

KPIA combines an LLM agent, structured product tools, and RAG retrieval. Its intended flow is: customer requirement → clarification when needed → product search/retrieval → grounded response and source references where available → enquiry record or escalation. The system is decision support, not an autonomous transaction system, and is not intended to place orders, move money, or perform irreversible actions.

## 5. Architecture

User/sales representative → Next.js/React chat interface → LLM agent orchestrator → structured product search and detail tools plus RAG retriever over approved Kentainers knowledge → evidence-grounded response, clarification, or escalation → enquiry persistence and follow-up.

The repository documents PostgreSQL/pgvector ingestion and retrieval with a local catalogue retrieval path. Runtime behavior depends on valid API/database configuration and the deployed build.

## 6. Data and Knowledge

The project uses Kentainers product catalogue and product-knowledge assets. Repository documentation reports a structured catalogue of 112 product records. Product sources are intended to be the source of truth for documented facts. Current prices, stock, delivery dates, warranty, certifications, compatibility, and technical values must not be invented; unsupported questions should be clarified or escalated.

## 7. Evaluation Method

The repository contains `eval/kpia-test-cases.json`, `docs/KPIA_TEST_BANK.md`, and evaluation runners referenced in `package.json`. Project documentation reports a 110-question product-intelligence test bank and agent/tool scenarios. Recommended sequence:

```bash
npm install
npm run build
npm run ingest:pgvector
npm run eval:baseline
npm run eval:agent
```

These commands must be run in the configured environment. The available evidence does not justify a final accuracy percentage, RAGAS/DeepEval score, latency figure, or measured improvement percentage. Those values remain pending until generated by actual runs.

## 9. Reliability and Safety

KPIA should avoid unsupported claims, clarify ambiguous requirements, and escalate when evidence is missing or conflicting. Evaluation should cover malformed input, missing knowledge, retrieval/tool failures, and prompt-injection attempts. The final capstone requires one real failure trace, root cause, targeted fix, and before/after regression evidence. No root cause is claimed without a reproducible trace.
